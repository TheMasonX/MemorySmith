# MemorySmith Chat Capability Improvements Audit

Date: 2026-05-18  
Audited plan: `MemorySmith.Core/Docs/Plans/ChatCapabilityImprovements_20260518.md`  
Audit scope: chat capability plan, live codebase, project wiki records/pages, tests, prior repo memories, and end-user fit for external MCP agents, internal chat agents, and human web portal users.  
Branch observed: `feature/chat-capability-improvements-plan`

## 1. Summary

The plan is accurate and well grounded: it correctly identifies that MemorySmith already has a useful chat/MCP foundation, but native tool calling, shared tool registration, page tools, context budgeting, tool observability, and human review flows are not implemented yet. The highest-value next slice is a shared read-only tool registry plus page/unified retrieval tools and deterministic search/get intercepts, while keeping source bundle and writes gated.

### 3.4 Findings - Code Quality

| ID | Severity | Finding | Evidence | Reasoning and impact | Recommendation | Confidence |
|---|---|---|---|---|---|---:|
| C1 | High | JSON-intercepted tool parsing is intentionally brittle. | `ReadToolCalls` strips an optional fence, calls `JsonNode.Parse`, catches all parse failures, and returns no calls. | This is safe against accidental prose execution, but it fails natural tool-use requests and produces the exact user symptom when the model explains tool incompatibility instead of returning JSON-only. | Preserve strict parsing as fallback, but add deterministic intent intercepts for explicit user commands and native tools where supported. | 0.98 |

| C3 | Medium | Argument parsing and validation are manual and duplicated. | Chat and MCP each read query/tags/status/limit/context-pack args separately and clamp in local helper methods. | New tools will multiply ad hoc parsing.
